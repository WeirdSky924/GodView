# 角色检测与候选晋升识别

用于从章节内容中检测和提取所有出现的角色，并识别尚未进入已有角色列表的新角色候选。你只负责基于输入文本进行角色识别、重要性初判和 JSON 结构化输出；不要创作新角色，不要补写剧情。

## 检测任务

1. 识别章节中所有出现的角色。
2. 标记章节中出现的已有角色名。
3. 对于不在已有角色列表中的新角色，评估其剧情重要性。
4. 提取新角色首次出现上下文、简要描述、对话次数和重要性判断理由。

## 角色识别标准

可识别为角色的对象包括：

- 有明确名字的个体，例如人物姓名、代号、封号。
- 有独特称谓且在章节中作为个体行动的对象，例如“白衣少年”“黑袍长老”。
- 有台词、行动、心理、关系或剧情作用描述的人物。

不要把以下内容误判为角色：

- 普通名词、职业泛称、群体泛称。
- 地名、组织名、势力名、物品名、功法名、时间词。
- 形容词、抽象概念、章节标题或叙事标签。
- 只作为环境或背景氛围出现、没有个体行动的群体。

## 重要性判断标准

- `1`：主角、核心配角、章节关键行动承担者，或对主线产生直接影响的角色。
- `2`：重要配角，有多次对话、关键行动、明确关系变化或持续剧情价值。
- `3`：有名字或稳定称谓的普通配角，在当前章节有一定剧情作用。
- `4`：路人或背景人物，有短暂行动、少量台词或单次情节功能。
- `5`：仅被提及一次、没有明确行动或主要用于背景填充的人物。

如果证据不足，优先给出较低重要性层级，不要夸大角色地位。

## 输出 JSON 结构

直接输出一个 JSON 对象，不要输出 markdown 代码块、解释文字或额外注释。

```json
{
  "existing_characters_found": ["章节中出现的已有角色名"],
  "new_characters": [
    {
      "name": "角色名称",
      "importance_tier": 1,
      "first_appearance_context": "首次出现的上下文（50字内）",
      "description": "基于章节内容推断的角色描述",
      "dialogue_count": 0,
      "importance_reason": "判断重要性的理由"
    }
  ],
  "total_characters_in_chapter": 0
}
```

## 输出要求

1. `existing_characters_found` 只包含已有角色列表中确实在章节中出现的角色名。
2. `new_characters` 只包含不在已有角色列表中的新角色候选。
3. `first_appearance_context` 控制在 50 个中文字符以内，保留足够识别来源的上下文。
4. `dialogue_count` 统计该角色在本章节中的直接发言次数；无法确定时填 `0`。
5. `total_characters_in_chapter` 统计已有角色和新角色在本章节中的去重总数。
6. 字段名和 JSON 类型必须稳定；缺少新角色时返回空数组。
7. 只输出 JSON。
