# 大纲上下文组装指南

在生成章节大纲前，必须先收集和整理项目的完整上下文信息。这确保大纲与现有设定保持一致，并能够充分利用已有的剧情资源。

## 一、必须获取的上下文信息

### 1. 角色信息

获取项目中所有角色的核心信息：

- **主角**：性格、目标、当前状态、成长进度
- **重要配角**：与主角的关系、最近动态
- **反派/对手**：当前威胁程度、近期行动
- **角色互动关系**：当前的紧张关系、联盟状态
- **角色可用性**：标准名/别名、importance_tier、narrative_weight、story_arc_role、plot_priority、状态、首次登场章节、退场章节、available_presence_types、当前位置与出场理由

**用途**：
- 确定本章直接可出场角色、仅可提及角色和不可出场角色
- 规划角色互动和冲突
- 推进角色成长线
- 防止在 POV/participating_characters 中使用别名、错误主角名、未登场角色、已退场/死亡/不可出场角色

### 2. 世界设定 (Lore)

获取与当前章节相关的设定信息：

- **力量体系**：当前阶段的等级、能力限制
- **地理位置**：场景可能发生的地点
- **势力格局**：相关势力的动态
- **关键规则**：不可违反的世界规则

**用途**：
- 确保场景设定符合世界观
- 避免设定冲突
- 合理安排能力展示

### 3. 伏笔状态

获取当前伏笔的管理状态：

- **待埋设伏笔**：计划中但未埋设的伏笔
- **已埋设伏笔**：等待合适的回收时机
- **待回收伏笔**：已经暗示或即将回收的伏笔
- **过期伏笔**：太久未处理需要关注的伏笔

**用途**：
- 规划本章要埋设的伏笔
- 选择本章要回收的伏笔
- 避免伏笔堆积或遗忘

### 4. 前文大纲

获取之前章节的大纲信息：

- **上一章大纲**：承接内容和结尾悬念
- **近期章节摘要**：剧情发展脉络
- **未完成的剧情线**：需要继续推进的内容

**用途**：
- 确保章节衔接自然
- 避免重复或遗漏
- 保持剧情连贯性

### 5. 项目元数据

获取项目的整体信息：

- **作品类型**：玄幻、都市、科幻等
- **叙事基调**：严肃、轻松、暗黑等
- **目标读者**：男频、女频、年龄段
- **当前进度**：已写字数、当前卷数

**用途**：
- 把握章节风格
- 调整节奏和密度
- 符合作品整体定位

## 二、上下文组装流程

### 步骤 1：确定章节位置

- 这是第几章？
- 处于哪一卷？
- 是开篇、中段还是结尾？

### 步骤 2：获取基础信息

```
项目ID → 获取角色列表 → 获取世界设定 → 获取伏笔状态
```

### 步骤 3：筛选相关信息

先生成 `character_availability_packet`：
- direct_available_characters：可进入现场、说话、行动、担任 POV、写入 participating_characters 的角色标准名；
- mentioned_only_characters：只能作为回忆、传闻、记录、消息、历史影响或离场后果被提及；
- unavailable_characters：不能安排为本章新行动或现场参与，需用户确认后才能改变状态/登场窗口。

`character_availability_packet` 约束的是“直接出场”，不是禁止一切叙事关联。请让 LLM 根据角色层级自行判断：
- direct_scene_presence：现场行动/对话/互动/POV，必须来自 direct_available_characters。
- explicit_mention：明确提及姓名/身份，不写入出场角色。
- indirect_influence：幕后计划、代理人、历史后果、制度压力影响本章，不写入幕后角色本人。
- foreshadowing_presence：异常、痕迹、象征、传闻、未知注视、系统波动等伏笔性存在，不写入出场角色，也不应自动变成角色绑定需求。

示例：第一章可以出现“无法解释的系统波动像某种更高权限留下的痕迹”，这是 foreshadowing_presence；不等于最终大反派直接出场。

不是所有信息都需要，要根据章节位置筛选：

- 开篇章节：侧重世界观介绍、角色出场
- 中段章节：侧重剧情推进、角色成长
- 高潮章节：侧重冲突升级、伏笔回收
- 结尾章节：侧重剧情收束、伏笔清理

### 步骤 4：构建上下文摘要

将筛选后的信息整理成结构化摘要：

```json
{
  "chapter_position": {
    "number": 15,
    "volume": 1,
    "phase": "rising_action"
  },
  "characters": {
    "main": {"name": "...", "status": "..."},
    "appearing": ["角色A", "角色B"],
    "relationships": ["紧张", "联盟"]
  },
  "world_settings": {
    "power_level": "筑基期",
    "location": "青云门",
    "active_factions": ["正道", "魔门"]
  },
  "hooks": {
    "to_plant": ["神秘身世暗示"],
    "to_resolve": ["师父的秘密"],
    "urgent": ["失踪的师兄"]
  },
  "previous_summary": "上一章主角突破成功，但发现师父神色异常..."
}
```

## 三、上下文使用原则

### 1. 一致性原则

- 所有内容必须与已建立设定一致
- 不引入与世界观冲突的新元素
- 角色行为符合已塑造的性格

### 1.1 角色知识边界原则

完整上下文是给 Agent 用来保证设定不冲突的，不代表所有角色都知道这些信息。使用上下文时必须区分：

- **作者/系统知道**：宪法级设定、国家级机密、隐藏真相、未来规划；用于保持世界一致性。
- **读者可知**：本章可以通过旁白、非主角视角或明确展示让读者知道的信息。
- **POV/主角可知**：角色基于身份、经历、地点、权限、能力、关系和本章线索能够合理知道的信息。
- **角色不可知**：角色当前身份无法接触、没有线索来源、没有权限理解的信息。

主角的行动依据只能来自 POV/主角可知信息。高密级设定可以影响事件发生，但若没有可信获取路径，只能表现为异常、后果、传闻、符号、代理人行动或未解释线索。

示例：贫民窟主角可以看到“巡逻队封锁旧巷、邻居失踪、墙上残缺徽记”，但不能直接知道“国家级清洗协议已启动”。后者只能作为作者侧真实因果或后续伏笔。

### 1.2 事件因果链原则

筛选上下文时，不只找“能制造钩子的素材”，还要找能支撑事件成立的因果材料：

```text
前因/背景压力 → 触发机制 → 主角卷入路径 → 阻力/选择 → 结果 → 后续影响
```

如果上下文里没有足够因果材料，不要随机制造国家机密、灾难、高阶人物或神秘物品；应降低事件规模，或在大纲中标注需要补充设定/资源。

### 2. 延续性原则

- 承接上一章的结尾和悬念
- 继续推进未完成的剧情线
- 保持角色发展轨迹

### 3. 平衡性原则

- 新信息与已有信息平衡
- 剧情推进与角色展示平衡
- 新伏笔与伏笔回收平衡

### 4. 服务性原则

- 上下文服务于章节目标
- 不堆砌无关信息
- 聚焦于推动剧情的核心元素

## 四、特殊场景处理

### 场景 1：开篇章节

- 侧重角色介绍和世界观铺垫
- 少量伏笔，避免过早暗示
- 建立读者期待

### 场景 2：过渡章节

- 快速推进，承接上文
- 为下一章高潮铺垫
- 适度角色互动

### 场景 3：高潮章节

- 大量伏笔回收
- 角色关系剧变
- 情绪强度拉满

### 场景 4：收尾章节

- 清理残留剧情线
- 处理未回收伏笔
- 为下一阶段铺垫

## 五、上下文更新

在生成大纲后，需要更新上下文状态：

1. 更新角色状态（如有重大变化）
2. 记录新埋设的伏笔
3. 标记已回收的伏笔
4. 更新章节摘要
